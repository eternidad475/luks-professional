# CaseFlowのサービス制限中の表示と再確認

2026-09-16。SupabaseのHTTP402・通信失敗を、招待未承認や契約なしと混同していたため、接続確認専用の表示を追加。

- 利用資格の照合に失敗した場合は利用を許可せず、再登録・招待コード入力へ誘導しない。
- 利用制限を確認できた場合は、その理由を日本語で表示。制限解除日は断定しない。
- 「接続を再確認」は現在のセッションを読み直し、プロフィールと契約を再照合する。ページの再読込・ログアウト・ブラウザー保存データの削除を行わない。
- 複数回押した場合は一つの処理にまとめる。古い応答で、ログアウトや別アカウントの状態を上書きしない。
- 権限確認は20秒で中断し、確認不能として扱う。旧スキーマへのフォールバックは列不足のエラーだけに限定。
- 本番認証ゲート、生成のトークン確認、ライブラリ保持期間は変更していない。

`node scripts/verify-access-recovery.mjs` で実ソースから抽出した関数を模擬応答で確認する。17項目には402、通信断、正規の許可・拒否、旧スキーマ、競合応答、再確認の二重実行防止を含む。全81本のインラインスクリプトの構文も確認。

これは障害時の表示・再試行の改善であり、Supabase側の制限解除や実アカウントの復旧を証明しない。症例・画像の書込み試験は実施していない。
